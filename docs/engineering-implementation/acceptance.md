# Physical Mac acceptance and release readiness

The operator confirmed successful normal-use dictation on installed 3.0.2 (`3dfd80c4e277b3d9`) and reported that the earlier Option-key and erroneous private-field issues were resolved in that usage. The full physical acceptance matrix remains open. [Verification record](../TESTING.md#physical-acceptance)

Use a disposable macOS account with synthetic clipboard values and private, unsent test fields. Record the candidate fingerprint, macOS version, permission state, intended field, observed output and verdict for each case. Use the read-only bundle smoke probe before starting. Avoid personal messages, real passwords and shell command prompts during input trials.

| Gate | Physical test and success condition |
|---|---|
| Audio on the built-in microphone | Dictate 20 synthetic phrases, including quiet, short and longer utterances. Confirm recording starts and stops cleanly and no cancelled utterance posts. |
| USB and AirPods | Try built-in, USB and Bluetooth input. Disconnect and reconnect during and between sessions. Confirm interruption safely ends capture and the next press recovers. |
| Hold, toggle and both Options | Exercise rapid presses, duplicate events, both sides and both release orders, Escape, and ordinary Option shortcuts. Confirm no stuck recording or repeat delivery. |
| Permission changes | Test initial prompts, permission denial, revoked Accessibility, Input Monitoring and Event Posting, and recovery after grant. Verify no permission reset is required. |
| Secure and unverified fields | Use a synthetic password field, a field with incomplete AX metadata and an ordinary editor. Switch during capture and during inference. Confirm no protected payload appears in the field, History, clipboard, notifications, logs or pill. |
| Foreground insertion | Try TextEdit, native search fields and explicitly chosen browser and editor controls. Compare the full displayed text, caret, selection, trailing space, focus and output from both delivery modes. Switch windows and tabs during processing. Record unsupported controls by name and version. |
| Clipboard and Undo | Use synthetic RTF, image and file items and copy another synthetic item during paste. Confirm the new copy is retained and standard manual Undo affects the correct stack. |
| macOS lifecycle | Exercise screen lock, sleep and wake, fast user switching, multiple displays and Spaces, accessibility display settings and Reduce Motion. Confirm the pill remains nonactivating and the next session starts cleanly. |
| Login and upgrade | In the disposable account, inspect bundle path, app fingerprint, strict signature and runtime. Test clean install, login opt-in, application restart, upgrade with login enabled and disabled, and relaunch. |
| Resource and latency | Record at least 20 physical attempts per promoted configuration. Measure release to visible text directly. Run a workday soak with repeated model switches and sleep/wake to measure stability and energy. |

Native login job restoration was simulated in regression tests and the bundle was signed and bootstrapped without starting dictation in a disposable home. Ad-hoc signature verification is a local check. Developer ID distribution and notarization are outside this release candidate.

The maintainer approved 3.0.2 source publication based on successful normal-use dictation and passing automated tests. The cases below remain available for follow-up verification. Use sanitized case verdicts when documenting a run.

## Operator run for candidate 3dfd80c4e277b3d9

**Full clean-build matrix pending.** This procedure records individual foreground, hardware and lifecycle results. Use a disposable local login or a separate Apple Silicon test Mac. Keep the account signed out of cloud sync and browser profiles. A temporary HOME in the daily login still shares its keyboard session, general pasteboard and login services.

1. Transfer the reviewed candidate source into the test login. From that directory run the [source fingerprint command](../ARCHITECTURE.md#installation-and-rollback). Expect `3.0.2 3dfd80c4e277b3d9`. Install in that login using `./install.sh`. Check the signature and bundle fingerprint with the same instructions. Quit the test app and provision small.en using the included CLI as shown in the [README](../../README.md#set-up-a-model). For medium.en, run `"$HOME/Library/Application Support/VoiceToText/runtime/.venv/bin/hf" download mlx-community/whisper-medium.en-mlx config.json weights.npz --revision 8d0335069b551e8586b8a4680674403d9417dfe4`. Reopen the app from the test login’s Applications folder. The locally built alias depends on its test-account runtime.
2. Initially deny the requested grants and inspect **Check permissions**. Grant Microphone, Accessibility and Input Monitoring to the test app in System Settings, relaunch if requested, then verify all four reported states, including Event Posting. Repeat after revoking and regranting each applicable permission in the test login. Record whether capture or delivery was blocked as appropriate. A system-wide TCC reset is unnecessary.
3. Open the [offline test fields](acceptance-fields.html) from disk in separate Safari and Chrome windows. Open an untitled plain-text TextEdit document, an untitled VS Code editor with no project or terminal open, and a new **On My Mac** note in Notes. For ChatGPT, use an unsent composer with synthetic text. Prepare a second disposable field, window or note for focus tests. Preload only a synthetic clipboard value such as `board apricot 17`.
4. Start in TextEdit with the built-in input and small.en. Hold Left Option, say “The blue cup is on the shelf,” then release. Look for the pill during capture and exactly one insertion at the caret. Repeat in toggle mode using a full press to start and another to stop. Try quick consecutive phrases with distinct numbers, both Option release orders, ordinary Option shortcuts and Escape during recording and inference. Check the next successful turn for a stuck mic, stale text or duplicate delivery.
5. For each editor and each insertion mode, try a caret, a selected word and adjoining text such as `café 🙂 尾`. Check displayed text, Unicode neighbors, selection replacement, trailing space and manual Undo. Record the actual decoded string in the disposable session when assessing Unicode fidelity. The automated payload cases exercise exact emoji and combining sequences. If dictation never produces a specific sequence, mark foreground delivery of that sequence untested. Switch field, caret, tab, window and application while holding and after release. Require zero writes to unintended destinations. An ordinary focus change during inference may leave an eligible result in History.
6. Start in the synthetic password field, then try the read-only field. Next, start in A and switch to the password field during capture and during inference, leaving it focused through completion. Use a distinct spoken marker. Check History, both fields, clipboard, pill, notifications and **only the test account’s** app log for that marker. Stop on any exposure or wrong-target write. Try paste with a synthetic rich-text selection, image and file, then copy a different fixture while auto-paste is pending. Verify the original representations return while owned and that the newer copy survives.
7. Switch the system input to AirPods or a USB mic if present. Repeat normal dictation, disconnect during capture, reconnect and try the next turn. In the same disposable fields, lock and unlock, sleep and wake, and change Spaces or displays. Try Reduce Motion, watch the pill for stale animation and keyboard focus loss, and verify the menu stays responsive. Report unavailable hardware explicitly.
8. Work offline with both models cached. Switch small → medium → small and wait for readiness each time. Edit and **Reload vocabulary**, clear the file and relaunch. Check low-confidence recovery when a controlled low-confidence result occurs. A result offered for review must remain out of the target until explicitly copied. Record an unobserved state as untested.
9. In the test account only, start with login disabled and log out and in. Verify no automatic start. Run `./install.sh --enable-login`, repeat the login and check for exactly one working app. Exercise upgrade with login disabled before enabling it, and again with login enabled. Verify the fingerprint, settings, vocabulary and next dictation after each.
10. Take at least 20 release-to-visible observations per configuration being promoted. Record the first visible text in the disposable editor, including missed, partial or late trials in the denominator. Use a timer or frame counts from a view of only the test field and the key release, with audio capture off. Report median and p95 separately from the menu’s release-to-post reading. Run the workday soak with scheduled input, periods of idle time, model switches and sleep/wake. Sample CPU, memory and responsiveness at the beginning, after each switch and at the end.

Use one line per case in the following format. Keep raw logs, recordings, clipboard bytes and document contents out of the repository.

```text
Case | build | OS/app version | input | model | insertion mode | attempts | observed result | pass/fail/untested/unavailable | latency if measured
```

Return the first failing case with its synthetic action sequence, app version and observed result. Treat a wrong destination, protected-data exposure, stuck capture or unrecoverable install as a failed case. Review individual app compatibility and physical latency before advertising support.
